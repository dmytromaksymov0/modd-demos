# modd. — стандарт качества демо-сайтов

Это портфолио веб-студии modd. Каждый сайт должен выглядеть как работа агентства за $3–5k, а не как сгенерированный лендинг.

## Стек
- Astro 7 (последняя стабильная, `npm audit` без критических уязвимостей) + Tailwind CSS 4, статическая сборка, деплой на Cloudflare Pages.
- Без тяжёлых UI-библиотек. Анимации: CSS или небольшой JS (Motion One / GSAP только если реально нужно).
- Шрифты self-hosted через @fontsource (не Google Fonts CDN). Для украинских сайтов — только шрифты с кириллицей.
- Изображения: только локальные файлы, оптимизация через astro:assets (AVIF/WebP, srcset, lazy).

## Фото и графика
- НИКАКИХ нарисованных кодом иллюстраций вместо фото, никаких canvas-заглушек, никаких серых плейсхолдеров.
- Реальные фото с Unsplash / Pexels (лицензия разрешает коммерческое использование). Скачивай в `src/assets/photos/`, веди `CREDITS.md` с автором и ссылкой.
- Подбирай фото под конкретную нишу и гео: американский пригородный дом для кровли, украинский интерьер для украинского бизнеса, а не стоковые улыбки на белом фоне.
- Если нужного фото нет — скажи мне, а не подменяй рисунком.
- Иконки: Lucide или Phosphor, один набор на сайт.

## Конкуренты — это пол, а не потолок
- Сайты конкурентов показывают, с чем работает ниша: какие блоки, офферы, страхи и сценарии нужны. Это берём как функциональную основу.
- Но конкуренты — НЕ образец исполнения. Обойти слабый рынок одной «сдержанностью» недостаточно. Каждый взятый у них приём делаем заметно лучше: точнее текст, сильнее визуал, удобнее взаимодействие, быстрее загрузка.
- Ориентир уровня дизайна и разработки — лучшие сайты вне ниши: премиальные бренды, архитектурные и продуктовые студии, сайты уровня Awwwards / Godly / Land-book. Ниша задаёт содержание, ориентир — качество.
- Превосходство должно быть измеримым: замеряем Lighthouse / Core Web Vitals конкурентов и показываем, что наш сайт быстрее, доступнее и чище.
- На каждом сайте нужны 2–3 «фирменных момента»: взаимодействия или визуальные решения, которых нет ни у одного конкурента и которые запоминаются в портфолио.

## Дизайн
- До кода — всегда фаза направления дизайна (3 варианта moodboard-описанием + 1 HTML-превью первого экрана для каждого). Я выбираю.
- Запрещённые клише: кремовый фон + серифный заголовок + терракота; почти чёрный + кислотный акцент; фиолетово-синий градиент; Inter / Space Grotesk / Poppins как «безопасный» шрифт; эмодзи как иконки разделов; всё по центру; одинаковые карточки с одинаковой тенью везде; нумерация 01/02/03 там, где нет реальной последовательности.
- Дизайн-токены (цвета, шрифты, шкала размеров, отступы, радиусы) — в одном месте (`src/styles/tokens.css` + tailwind theme). Никаких захардкоженных цветов в компонентах.
- Сетка и ритм: единая шкала отступов, максимум ширины текста ~65 символов.
- Светлая тема обязательно; тёмная — только если она уместна для бренда.

## Контент
- Компании вымышленные, но тексты — как у реального бизнеса: конкретные цены, сроки, районы, термины ниши. Никакого lorem ipsum и воды вроде «мы команда профессионалов».
- Отзывы — НЕ выдумывать как настоящие. Блок отзывов помечается «Sample reviews — replaced with real Google reviews at launch» / «Приклади відгуків».
- В футере: «Concept site · fictional company · designed & built by modd.»
- Телефоны: американские 555-xxxx, украинские явно демонстрационные.

## Конверсия (сайт должен приносить заявки — это наш оффер)
- Главное действие (звонок / запись / заявка) видно на первом экране и в sticky-панели на мобильном.
- Формы реально работают: отправка в Telegram-бот через Cloudflare Pages Function (`functions/api/lead.ts`), токен и chat_id из env. Валидация, понятные ошибки, состояние успеха, honeypot от спама.
- Микроразметка schema.org (LocalBusiness / Dentist / AutoRepair / VeterinaryCare и т.п.), title/description на каждую страницу, Open Graph картинка.
- Аналитика: заготовка под GA4 / Plausible (выключена в демо).

## Качество (я QA — проверяю жёстко)
После каждой фазы сборки:
1. Скриншоты Playwright: 375, 768, 1280, 1920 px, полная страница, каждая страница сайта. Сохраняй в `screenshots/` и сам их просматривай.
2. Самокритика по скриншотам: выравнивание, ритм отступов, переносы заголовков, обрезанный текст, пустые места, контраст. Исправь, перескриншоть.
3. Lighthouse (mobile): Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO = 100. Отчёт в `reports/`.
4. Нет горизонтального скролла ни на одной ширине. Нет ошибок в консоли. Все ссылки и якоря рабочие.
5. Клавиатурная навигация и видимый focus. prefers-reduced-motion уважается.
6. Короткий отчёт: что проверено, что исправлено, что осталось.

## Процесс
- Работай по фазам, после каждой — остановка и мой «ок».
- Не делай всё одним махом. Строй страницу секция за секцией, проверяя каждую.
- Если что-то в брифе неясно — спроси, а не додумывай.
- На фазах 1–3 используй скилл `ui-ux-pro-max` (установлен глобально в `~/.claude/skills/ui-ux-pro-max`): `--design-system` для направления, `--domain`/`--stack` для точечных вопросов. Его результаты — рекомендации, запреты из этого файла важнее.
- Playwright стоит в корне `modd-demos/` (`node_modules` общий для всех сайтов).

## Git и деплой
- Все сайты живут в одном приватном репозитории `dmytromaksymov0/modd-demos` (ветка `main`), каждый в своей папке. Коммит и пуш — только по моему «ок».
- `screenshots/` и `reports/` сайта в git не попадают (см. `.gitignore`): итоговые цифры QA пиши в `docs/`.
- Деплой — **только через Git-интеграцию Cloudflare Pages**. Никакого Direct Upload (`wrangler pages deploy` в новый проект): такой проект потом нельзя подключить к GitHub, придётся пересоздавать и менять адрес (так уже было с Kestrel).
- Порядок: код закоммичен и запушен → основная сессия создаёт Pages-проект с Git-источником через Cloudflare API (токен с правом Pages: Edit лежит в Связке ключей macOS как `cloudflare-pages-modd`, значение никогда не выводится) → дальше каждый пуш в `main` публикует сайт. Если API недоступен — я создаю проект в дашборде через «Import an existing Git repository» (не мастер Workers).
- Настройки проекта: Root directory = папка сайта, Build output = `dist`, Build command = `npm run build`, `NODE_VERSION` = `22`, Build watch paths = `<папка сайта>/*`.
- Имя Pages-проекта выбираем до первого деплоя (переименовать нельзя) и держим одинаковым в трёх местах: имя проекта в Cloudflare, `name` в `wrangler.toml`, `site` в `astro.config.mjs` (+ `robots.txt`).
- Перед тем как предложить имя, проверь, что адрес `<имя>.pages.dev` свободен: `curl -s -o /dev/null -m 10 -w '%{http_code}' https://<имя>.pages.dev/`. Любой HTTP-код (200, 404…) — имя занято другим аккаунтом, и Cloudflare выдаст адрес с суффиксом (так вышло с Brightwater → `brightwater-dental-ba5`); `000` (нет ответа) — скорее всего свободно. Предлагай мне 2 свободных варианта. Если после создания проекта адрес всё равно получил суффикс — переведи `site`, `robots.txt` и все абсолютные ссылки на фактический адрес.
- Лимит Cloudflare — 5 Pages-проектов на репозиторий: ровно по одному на сайт, тестовые проекты не создаём.
- Секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) ввожу я сам: дашборд или `npx wrangler pages secret put … --project-name <имя>`. После добавления — Retry deployment. Тестовую заявку в Telegram отправляй только с моего разрешения.
